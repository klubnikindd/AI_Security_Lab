## 🟡 P1 — Важные (запланированы, не блокируют PoC)

- [ ] **Rate Limiting работает в памяти** — небезопасно при горизонтальном масштабировании.
  - *Решение:* Redis (см. [Roadmap](README.md#-roadmap-to-production))
- [ ] **Отсутствует аутентификация на `/chat`** — эндпоинт открыт.
  - *Решение:* JWT / API-ключи (см. Roadmap)
- [ ] **Ненадёжный URL allowlist** — поиск по подстроке (`github.com.evil.example` обойдет защиту).
  - *Решение:* полноценный парсинг URL и строгое совпадение hostname.
- [ ] **Нет замера ASR после внедрения защиты**
  - *Решение:* прогон Garak через REST-эндпоинт `/chat` (в процессе).

## ⚪ P2 — Принято к сведению, пока не планируется

- **OpenTelemetry / распределенный трейсинг** — PoC работает в одном экземпляре, логов в stdout и метрик Prometheus достаточно.
- **Интеграция с SIEM (ELK/MaxPatrol)** — вне зоны ответственности PoC, актуально только для продакшена.
- **Английская версия README** — пока только на русском.

## 🚫 Явно вне рамок проекта (Out of Scope)

Чтобы задать верные ожидания: это **исследовательский PoC**, а не корпоративный продукт. Следующие пункты **намеренно не реализованы**:

- Высокая доступность (HA) и горизонтальное масштабирование.
- Развертывание в изолированных сетях (Air-gapped).
- Соответствие требованиям ФСТЭК / 152-ФЗ / 187-ФЗ.
- Мультитенантность (Multi-tenancy).
- Гарантии SLA / SLO.

Все это относится к [Плану перехода в Production](README.md#-roadmap-to-production), а не к текущему PoC.
